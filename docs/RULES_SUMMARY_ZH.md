# 核心判定：讲解简版

沿用此前讨论中的符号，以下是便于讲解的归纳式，不是逐字转录 Notion 原公式，也不新增实现规则。

| 符号 | 意思 |
| --- | --- |
| $\Gamma_{\mathrm{decl}}$ | 论文声明的攻击者信息权限：允许什么、禁止什么 |
| $D_{\mathrm{impl}}$ | 实现证据：什么信息实际到达攻击构造或优化过程 |
| $R$ | 对照两者后给出的判定 |
| $e$ | 一条待核查的信息流 |

## 1. 先对齐范围

只比较同一目标接收边、阶段、实验条件以及政策覆盖的信息粒度和实例范围。基准设计者或评分器读取任务，既不证明攻击生成器读到，也不证明它没读到；训练与测试的实例相同或不同都需要证据。完整 query、部分 query 和任务主题分别记录。仅限同评测实例的禁令需要核实同一实例；明确禁止任意实例的某类信息时，不额外强求同评测实例，训练访问也可能违规。明确的具体授权或诊断限定也要纳入。

## 2. 不一致＝明确禁止＋确认交付

在上述范围已对齐、权限确实适用且证据无冲突的前提下：

$$
\bigl(\Gamma_{\mathrm{decl}}\vdash\operatorname{deny}(e)\bigr)
\land
\bigl(D_{\mathrm{impl}}\models\operatorname{present}(e)\bigr)
\Longrightarrow R(e)=\text{不一致}.
$$

这里禁止的是攻击者取得某类信息；present 必须有信息到达构造／优化端的证据。数据集里存着 query、评分器知道答案、攻击突破受害者安全目标，都不能单独满足这条规则。

明确且适用于目标边的 allow 足以排除该“禁止访问”怀疑，无须额外证明已经实际访问。评分器边的 present 与攻击者边的 excluded 不构成冲突；同一攻击者边的 present 与 excluded 仍须保留冲突。若目标固定为攻击者，只见评分器访问仍是证据不足。

## 3. 每篇论文只汇总一次，保留三种结论

| 证据情况 | 论文结果 |
| --- | --- |
| 至少一条信息流确认不一致 | 不一致，并说明具体范围 |
| 没有确认不一致；所列怀疑非空、全部有证据排除，且覆盖完整 | 范围内一致 |
| 权限未说明、路径未确认、证据冲突或范围未闭合 | 证据不足 |

**没写允许，不等于明确禁止；没找到读取，不等于证实没读取。** 更强投递通道，也不自动意味着更多任务知识。

ASPI 的例子：对照 §3 任务知识限制与固定发布版 Stage 2 的部分任务输入，可确认限定的构造不一致；发现定位于相应 `clarif_user` 路径，不能自动推广到其他通道或作者历史运行。

## 另一个独立问题：这些信息是否提高了攻击效果

$$
\Delta\mathrm{ASR}=\mathrm{ASR}_{\mathrm{full}}-\mathrm{ASR}_{\mathrm{limited}}.
$$

这项对照衡量信息的行为影响，不进入上面的 $R$。没有显著提升不能抹去已证明的构造差异；构造差异也不证明 ASR 被抬高。因果解释仍需控制其他实验差异。

讲解时可直接说：**先把论文与实现放在同一范围比较；若明确禁止的信息实际进入攻击构造，就报告不一致；证据闭合才能排除怀疑，缺证据就保留未定。攻击效果再单独做消融。**
