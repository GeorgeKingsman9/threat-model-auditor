# 只给论文输入的自动工作流

普通使用方式只有两个必要输入：**论文文件/网址，以及新输出目录**。用户不用先找出不一致、写 cases、选择 `allow/deny` 或制作 gold。

```bash
python3 -B scan.py input.pdf --output outputs/my-paper
python3 -B scan.py https://arxiv.org/abs/2605.17324v1 --output outputs/from-url
```

以下说明默认单篇入口；历史人工回归和仅 PDF 测试仍有各自版本与结果，不会被新流程覆盖。

## 1. 从原始论文开始

`documents.load_document()` 读取本地 PDF/HTML/TXT 或公开 HTTP(S) URL。arXiv abstract 链接可转换到 PDF；部分 landing page 可跟随明确 PDF 链接。读取设置有限额与超时；无法取得正文的访问挑战页不能当论文审计。

PDF 提取保留页号、内容 hash 和可用的阅读顺序视图。图像/扫描页没有自动 OCR；仅有部分 HTML 文本时，不能据此声称全文覆盖。

PDF 输入由 Poppler 的 `pdftotext` 或可选 `pypdf` 处理。后续推理默认使用已保存的 ChatGPT/Codex CLI 登录，使用该账号额度；不要求用户另配 Claude API，也不保证额度使用免费。

## 2. 自动发现明确关联的官方源码

默认入口继续检查论文材料与支持的关联入口中的代码来源。它寻找的是**有明确论文归属证据的实现**，不是任意出现的 GitHub URL。

发现记录应保留：候选 URL、从哪里读到、为何认为与该论文关联、选择了什么，以及因歧义或缺失而没有选择什么。比如相关工作或依赖库引用，不能仅凭仓库可访问就当作作者实现。

这是有界的链接/关联发现，不是对所有项目页、搜索引擎、私有仓库、补充材料网站的完整搜索。没有发现源码不等于源码不存在；当前访问不到也不等于作者没有公开过。

当前自动源码快照入口支持公开 GitHub 仓库；其他托管服务尚未自动接入。PDF 的 URI 注释可以补全同页明确代码声明对应的断行链接，但链接存在本身不能证明它是作者实现。

代码可用性声明允许段内排版换行，例如 `Our code and data` 与 `are available at:` 分成两行；空行隔开的段落仍分开，不把其他工作的链接当成作者源码。

有三种应分开报告的状态：

| 发现情况 | 后续行为 | 结论边界 |
| --- | --- | --- |
| 明确关联且可支持读取的官方源码 | 固定版本、读取快照，进入论文＋源码 V4 流程。 | 只覆盖本次选入的版本、文件与构造路径。 |
| 没有找到明确来源，或多个候选归属不清 | 保留发现记录，继续只审论文文本。 | 无法验证实际实现；缺失本身不能产生 negative。 |
| 明确选定来源，但抓取/解析失败 | 保留该步骤失败和原因。 | 不能把失败转换成源码已审计，或隐藏为“没有问题”。 |

普通用户不需要据此手写证据 JSON。需要审查的是程序本次留下的关联依据与范围。

## 3. 固定源码并实际读取

明确选定仓库后，程序记录固定提交或本地内容身份、文件清单、原字节 hash、行号及遗漏原因，再把选入源码文本送给模型。只在报告里显示仓库链接，不能称为已经审计源码。

公开GitHub来源先尝试完整archive，最多约90秒。遇到暂时网络错误或下载体积上限时，转为同一固定commit的完整Git tree与源码文件读取：只下载符合现有过滤规则的文件，逐层核验Git tree、逐文件核验Git blob SHA和SHA256。备用方式最多128个源码文件、4路并发、单请求最多20秒、每个请求最多2次；总elapsed检查预算160秒。底层阻塞读取可能略晚于预算返回，但超时完成的快照不会被接受。模型推理没有因此增加自动重试。

必须取得完整未截断tree；所有符合单文件体积限制的eligible源码都须读取并验证成功，再应用字符预算选择模型输入。任一应读文件失败、树不完整或hash不符，均不得把残缺内容作为有效源码快照。每次成功／失败／备用方式记录在 `source_acquisition.json`；全部失败仍保留记录并明确降级。

源码有选择预算和排除项。完整文件的选择与遗漏都须显式记录；部分覆盖可以支持一条限定的正面发现，但不能证明整个仓库不存在别的信息路径。

不会安装或运行作者依赖，不会执行仓库脚本、模型、攻击或受害者测试，也不会把仓库内的指令当成审计器指令。论文、源码、README 和模型提议均作为待审数据处理。

固定当前发布 commit，也不自动证明作者历史实验用了这个版本。若结论需要历史请求、运行配置或训练/测试样本归属，而输入没有提供，应保留缺口。

## 4. 自动抽取、独立复核与证据验收

取得明确论文＋源码输入时，V4 按以下顺序形成证据：

1. 第一次模型调用读取实际论文与源码片段，提出具体怀疑、政策类型、适用角色/阶段、信息表示及代码链。
2. 程序检查引文。如果少量引文不匹配且调用预算允许，可进行一次有界恢复：从预先校验的候选里选择指针或放弃，不能修改分类来凑结果。
3. 另一次独立复核调用重新检查原始材料和提议，分别判断政策适用与信息交付、代码链和实验分支。
4. 确定性规则核对引文、来源类型、路径连接、接收边界和实例关系，再汇总论文结果。

“独立复核”指另一次模型审查，不是独立人工确认，也不保证使用不同模型。精确引用证明某段文字存在，不能单独证明模型的解释正确。

程序需要的是同一个主体、阶段、信息实例和用途上的**适用限制＋实际交付**。以下情况分别处理：

- 声明明确允许 benign document 或给定 query，不能只因使用这些信息就判不一致。
- 训练实例和未来测试实例不能仅凭都叫 query 就合并；也不能把“训练”当成通用免责标签。
- 评分器/防御者读取真值，不等于攻击生成器得到真值。
- 攻击成功违反受害者安全目标，不自动等于论文违反攻击者知识预算。
- 没找到路径、来源不明或引用失败，不能写成“已证明没有路径”。

找不到/不能明确选择源码时，仅论文路径仍会抽取和复核，但只能使用论文中提供的证据。它不能借用已有人工案例、gold 或旧源审计结论，伪装成本次实际读过代码。

## 5. 一篇一行，证据链可展开

最终主表一篇一行。内部多个角色、阶段、流或代码步骤，是支撑这条论文结果的依据，不会增加论文分母。

输出至少应能回答：本次读了什么、源码怎样发现与固定、遗漏了什么、模型实际完成了哪些步骤、哪条引文/路径支持结论，以及还有什么未解决。

| 产物 | 用途 |
| --- | --- |
| 文档与源码发现记录 | 回查候选、明确关联依据、固定来源及放弃原因；没有源码时同样留记录。 |
| `prepared.json` | 论文提取文本、页段和 hash。 |
| `repository.json` / `combined_input.json` | 取得源码时保存其版本/清单/覆盖信息，以及本次论文＋源码绑定输入。 |
| `source_acquisition.json` | 完整archive及备用源码读取的尝试、字节数、耗时、错误分类与hash；失败同样保存。 |
| `request.json` | 提示版本、实际输入身份和限制。 |
| `extraction.json`、可选引文恢复文件、`review.json` | 对应实际完成的模型步骤；文件存在仍需结合格式/验收状态阅读。 |
| `inference.<阶段>.json` / `inference.json` | 每次模型步骤结束即保存调用账本；后续论文或下载失败不应抹掉已完成调用。 |
| `result.json` | 单篇终态、范围、证据、原因、失败或未解决项。 |
| `report.json`、`report.html`、`report.md` | 一行汇总和可展开的测试过程；HTML 可直接打开。 |

网络、解析、模型或限额错误应显示为失败，不得变成“没有不一致”。未运行模型时显示 `not_run`；模型调用用量没有报告时，也不能假定零用量。

仓库版本解析使用 GitHub [单条提交列表](https://docs.github.com/en/rest/commits/commits#list-commits)固定 SHA，避免为取得版本号下载整份提交 diff。HTTP 正文截断会被记录为材料不可用，不能接收残缺内容；每篇的最终异常边界保留失败记录，避免一篇中断整个批次。

`inconsistent` 是限定发现；`consistent_within_scope` 要有命名怀疑的具体反证；`insufficient_evidence` 是尚不能确认；`not_applicable` 是领域不适用。这几类与技术失败、未运行分别展示。

原文和原始模型输出保留在本地运行目录，默认不随 GitHub 仓库上传。公开过程视图应仅保留必要原创说明、来源位置、hash 和判定范围，避免把整份论文/源码作为报告复制发布。

## 6. 两个可选模式

### 仅审论文文本

```bash
python3 -B scan.py input.pdf --paper-only --output outputs/text-audit
```

该模式关闭自动源码发现与读取，保留只输入论文的路径。适合明确只核查文本描述的任务；它不能替代源码审计，也不能用完整证据 registry 的标签计算同等范围的自动准确率。

### 仅准备输入

```bash
python3 -B scan.py input.pdf --prepare-only --output outputs/preparation
```

此模式不调用模型，但默认仍可以访问公共论文链接、发现官方代码并读取明确来源，因此不能理解成“完全离线”。没有产生论文审计结论。

若也不希望进行源码发现：

```bash
python3 -B scan.py input.pdf --paper-only --prepare-only --output outputs/text-preparation
```

## 7. 高级用户可以覆盖来源

```bash
# 公开仓库的显式覆盖；不是普通使用的必填参数。
python3 -B scan.py input.pdf \
  --repo https://github.com/OWNER/REPOSITORY \
  --repo-revision FULL_COMMIT_SHA \
  --output outputs/explicit-repository

# 本地源码目录；仍只读，不执行仓库内容。
python3 -B scan.py input.pdf --repo /path/to/source --output outputs/local-source
```

覆盖来源不等于用户已经提供了正确结论。应核查它与论文是否对应、具体版本是什么，并保留人为覆盖的来源说明。`--paper-only` 与显式源码输入是不同模式，不应混用。

`--max-input-chars`、`--max-code-chars` 和调用预算用于限制读取/推理范围。输入超限或证据遗漏需要报告，不能静默截掉材料后声称完成全仓库审计。更多 V4 细节见 [论文与源码审计](PAPER_SOURCE_AUDIT_ZH.md)。

默认数据输入上限为 600,000 字符，源码正文选择预算为 320,000 字符。前者同时检查实际序列化的模型数据，包括源码清单、引文恢复请求和复核提案；超限即停止该步骤。`--prepared-dir` 仅复用论文提取结果，仍会重新发现、固定源码，不能当成冻结源码的恢复入口。

## 8. 用户审计与开发回归的区别

| 流程 | 输入 | 能说明什么 |
| --- | --- | --- |
| 普通 `scan.py` | 新论文 PDF/URL；程序自动形成来源与证据。 | 本次输入在实际覆盖范围内的审计结果。 |
| `scan.py --paper-only` | 新论文文本，不读取源码。 | 论文文本证据范围的结果。 |
| `scan.py --prepare-only` | 原始文档和可发现的源码。 | 仅说明材料准备情况，没有模型判定。 |
| `audit.py` / 已有 cases 规则回放 | 人工规范化证据。 | 规则是否按给定前提工作，不证明自动发现证据。 |
| `evaluate` / gold 事后比较 | 已产生的结果与单独保存的参考标签。 | 开发回归一致性；不是未见论文自动准确率。 |

未知新论文没有现成 gold 也应可以运行，且模型请求不能包含人工预期标签。已有开发案例和既有正确答案不能替代对新输入的读取。

## 9. 已有真实结果如何理解

[ASPI V4 实际运行](PAPER_SOURCE_RESULTS_ZH.md)从原始论文与明确给定的固定源码出发，完成新鲜抽取、有界引文恢复和独立复核，3 次调用后输出限定 `inconsistent`。它验证的是该固定输入的自动证据形成能力；默认来源发现仍需在具体运行中记录与检查，不能把旧成功当成所有新输入都能发现官方代码的证明。

旧 PDF 主测试、四个域内控制、人工原始资料重审与这次 V4 运行分别保留。源码/运行归档更丰富时，结果可能与 paper-only 不同；这种差异必须按来源与范围解释，不能回填旧输出或改 gold 掩盖。

当前尚未建立陌生论文上的端到端准确率、召回率或自动 negative 认证率；一篇已知案例的成功、规范化回归全匹配或四篇控制未再告警，都不能代替这些测量。

本次默认入口改动的真实材料预检见 [读取记录](results/2026-11-20-automatic-entrypoint/readiness.json)：ASPI 的 PDF 下载遇到 TLS 错误，Retrieval Barrier 与 MUZZLE 正文下载超时。三项均未进入模型审计，调用数为 0，不能记为新的 positive、negative 或不确定结论，也没有覆盖旧结果。
